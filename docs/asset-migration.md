# Перенос ресурсов в свои форматы

Статус: план, 2026-10-24.

Пользователь: «Да, разрешаю. Смотри, нам важно сделать вот этот шаг по переносу старой архитектуры на новую, а потом уже на основе этой новой архитектуры, чтобы нам было удобнее переделывать ресурсы, чтобы не зависеть от легаси, которое мы можем повыпиливать.»

Цель — сначала перевести все ресурсы Gothic в свои открытые форматы, а улучшать уже их. Движок грузит только эти форматы. Загрузчики форматов Gothic остаются запасным путём, пока не доказано совпадение, потом удаляются.

## Как работает сейчас

Готов конвертер меша мира; движок его ещё не читает.

- **Конвертер** [`scripts/convert/convert.cpp`](../scripts/convert/convert.cpp), цель CMake `content-convert` (ZenKit, без движка и окна):
  - `content-convert world <папка Gothic> NEWWORLD.ZEN <папка>` режет меш мира на куски и сразу читает их обратно и сравнивает с исходным мешем;
  - `verify-world … <папка> [папка правок]` сравнивает уже готовые куски;
  - `--self-test` — круг на синтетическом меше, без файлов игры.
- **Общий модуль** `common/worldchunks.{h,cpp}`: запись кусков, чтение (с правками поверх), канонический вид меша и побитовое сравнение. Его же возьмёт загрузчик движка.
- **Хоринис** (2026-10-24, Mac): 473 502 треугольника, 259 404 вершины, 707 658 признаков, 1 081 материал; 403 куска, 48 МБ; запись и проверка — 1,7 с. Прочитанный обратно меш побитово равен исходному. Вывод — `~/.local/share/gothic-ai/base/v1/worlds/NEWWORLD/`.
- **Blender** открывает кусок как есть: масштаб 0,01, `_VERTEX`/`_FEATURE` и запись материала (`extras` → свойства материала) переживают импорт и экспорт. Что теряется у куска, прошедшего через Blender: вырожденные треугольники (в куске `5_4` — 14 из 5 800), нормали сдвигаются до 0,4°, часть UV — на последний разряд, порядок треугольников между материалами. Позиции остаются точными.

Остальное, на что план опирается:

- **Каталог контента** `~/.local/share/gothic-ai/content` (или `OPENGOTHIC_CONTENT`). В нём наши замены поверх оригинала:
  - `materials/materials.json` подменяет текстуры по имени, в том числе на меше мира;
  - `meshes/meshes.json` подменяет визуалы предметов (`.MRM`) на `.glb`.
- **Загрузчик glTF предметов** `common/gltfmesh.cpp` — подмножество: только GLB, не больше 65 535 вершин, без цвета вершин, без группы `WATER`. Отдаёт `zenkit::MultiResolutionMesh`.
- **DDS** — только DXT1/3/5 со старым заголовком (`pixmapcodecdds.cpp`).
- **Перепись** `OPENGOTHIC_CENSUS` считает открытые файлы оригинала по видам.

Собрать и проверить конвертер:

```sh
cmake -S scripts/convert -B ~/.cache/gothic-ai/content-convert-build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build ~/.cache/gothic-ai/content-convert-build
~/.cache/gothic-ai/content-convert-build/content-convert --self-test
```

## Решения

| Вопрос | Решение |
|---|---|
| Что такое «сконвертированное» | Тот же ресурс Gothic в нашем формате, без изменений: те же вершины, UV, пиксели, материалы. Это контент оригинала: в git не кладётся и не раздаётся. Его строит скрипт из установленной игры пользователя, повторяемо, так что резервная копия не нужна. |
| Правка сконвертированного | Меш мира можно править как производную (решение пользователя 2026-10-24: «Да, разрешаю»): ступени, кромки, балки прямо в его геометрии. В реестре у такой правки вход `converted world mesh <мир>/<кусок>`, как у правок оригинальных текстур. Годится для ремастера поверх Gothic, не для полностью своей игры. Предметы по-прежнему строим сами: меш оригинала — только подложка. |
| Слои | Сверху вниз: **контент** (наши ресурсы и правки, `~/.local/share/gothic-ai/content`) → **база** (сконвертированный оригинал, `~/.local/share/gothic-ai/base/<версия>`, или `OPENGOTHIC_BASE`) → архивы Gothic (запасной путь, пока его не удалят). Правка куска мира лежит в контенте и перекрывает тот же кусок базы. |
| Ryzen | Как и с контентом: каталог базы по умолчанию на Ryzen не заполняем. Прогоны передают `OPENGOTHIC_BASE` явно. |
| Совпадение | Каждый вид переносится только после доказательства, что результат тот же: побитовое сравнение структур в памяти движка (меш, материалы, пиксели) по всем файлам вида, затем съёмка пар «архив / база» и проверки физики. Пока совпадения нет, база для этого вида выключена. |
| Мера | Перепись получает второе число: сколько файлов открыто **в формате Gothic**. Цель этого плана — ноль. Первое число, сколько ресурсов оригинала грузит игра, останется до этапа 9 [своего контента](own-content.md#этап-9-без-gothic). |
| Кто пишет код | Формат, конвертер и всё, что касается моделей и текстур, — Claude. Загрузчики движка и замена типов ZenKit внутри движка — Codex по брифу: проверка у них — тесты совпадения, не взгляд. |

## Формат

### Мир

Мир в базе — каталог `worlds/<МИР>/`:

- `chunks/<x>_<z>.glb` — меш мира кусками по сетке 64 × 64 м в плане. Треугольник идёт в кусок по центру. Кусок — единица правки: его открывают в Blender и кладут правку в контент под тем же именем.
- Внутри куска — один примитив на материал. Вершина glTF — пара «вершина, признак» оригинала: позиция, нормаль, UV и `COLOR_0` (свет вершины, его берёт ткань мира). Оси и единицы — как у предметов в `gltfmesh.cpp`: метры, X зеркален.
- Материал glTF несёт полную запись материала Gothic в `extras.gothic`: имя, текстура, цвет с альфой, `alpha_func`, группа (включая `WATER`), `disable_collision`, анимация текстуры, волна. Blender хранит `extras` как свои свойства и пишет их обратно при экспорте.
- Порядок треугольников оригинала — в `extras.gothic.order` примитива: номер каждого треугольника. По нему загрузчик восстанавливает исходный порядок. От порядка зависят ключ кэша навмеша, разрешение совпадающих треугольников в физике и номера поверхностей ткани. У куска, прошедшего через Blender, порядка нет: его треугольники идут после остальных, навмеш пересобирается.
- Вершина и признак узнаются по номеру в оригинале (`_VERTEX`, `_FEATURE`) вместе со значениями. Общая для двух кусков вершина снова становится одной, а сдвинутая правкой копия — отдельной вершиной. У новой геометрии номеров нет.
- Кусок с тем же именем в `content/worlds/<МИР>/` заменяет кусок базы.
- Флаги полигона и номер лайтмапа — тоже в `extras.gothic` на треугольник: их переносит ткань мира.

На первом шаге BSP, секторы, порталы, предметы и сеть путей по-прежнему читаются из `.ZEN`. Их перенос в свои файлы — отдельный шаг.

### Предметы

`meshes/<ВИЗУАЛ>.glb` в базе — тот же формат, что у наших предметов. Загрузчик расширяется: полная запись материала в `extras.gothic`, больше 65 535 вершин.

### Текстуры

`textures/<ИМЯ>.dds`. Текстура в DXT1/3/5 переносится копией блоков, без пережатия, поэтому пиксели совпадают точно. Несжатая — в DDS без сжатия, и Tempest учится её читать. Формат сохраняется: от DXT1 или DXT5 зависит, как движок классифицирует альфу материала.

## Шаги

| Шаг | Что | Готово, когда |
|---|---|---|
| П1 | **Меш мира Хориниса.** Конвертер `content-convert world` (ZenKit, CMake-цель), формат выше — готов. Загрузчик движка собирает из кусков тот же `zenkit::Mesh`, BSP и остальное — пока из `.ZEN`. Флаг `OPENGOTHIC_BASE`. | Меш из базы побитово равен мешу из архива: вершины, признаки, треугольники в порядке, материалы. Пары кадров на точках `city-intent.bench` без разницы сверх шума. Ключ навмеша тот же. Физика: лучи стенда `own-mesh-physics` и шаги героя дают те же материал и сектор. |
| П2 | **Правка куска.** Кусок из контента перекрывает кусок базы. Путь Blender → `.glb` с сохранением `extras`. Пилот — лестница порта со ступенями. | Лестница порта в игре со ступенями, по ней ходят, навмеш пересобран, вход в реестре — производная. |
| П3 | **Остальные три мира** — тем же конвертером. | Совпадение как в П1 для каждого мира. |
| П4 | **Текстуры.** Все 2 784 `.TEX` в DDS. | Пиксели каждой текстуры из базы равны пикселям из архива. Перепись: 0 открытий `.TEX`. |
| П5 | **Предметы.** Все 1 355 `.MRM` в `.glb`. | `PackedMesh` каждого визуала из базы равен собранному из архива. Перепись: 0 открытий `.MRM`. |
| П6 | **Данные мира.** BSP, секторы, порталы, предметы мира (vob), сеть путей — в свои файлы. | Игра грузит мир, не открывая `.ZEN`. Сохранения совместимы. |
| П7 | **Свои типы в движке.** `zenkit::Mesh`, `zenkit::Material`, `MultiResolutionMesh` внутри движка заменяются своими типами; ZenKit для этих видов остаётся только в конвертере. | Движок собирается без этих типов ZenKit вне конвертера. |
| П8 | **Удаление старых загрузчиков** мира, предметов и текстур. Запасной путь уходит. | Перепись: 0 файлов этих видов в формате Gothic на всех бенчах и e2e. |

Персонажи и анимации (`.MDM`, `.MDH`, `.MMB`, `.MAN`), звук, музыка, озвучка и скрипты в этот план пока не входят. Для них нужен загрузчик скелетов и анимаций glTF, а на скелет завязаны foot IK, взгляд, тело и бой. Решим, когда П1–П8 будут готовы.

## Риски

- **Порядок треугольников.** Разошёлся — тихо пересоберётся навмеш и сменятся номера ткани. Поэтому порядок в формате, и П1 проверяет ключ навмеша.
- **Имена секторов.** Сохранения и гильдии комнат читают имена материалов с `:` побайтно. Конвертер переносит их без изменений, П1 проверяет.
- **Размер.** Меш Хориниса — сотни тысяч треугольников. Куски по 64 м держат каждый `.glb` небольшим для Blender.
