# Стабильность эталона лучей для стоп

Расхождения флагов стоп на поздней лестнице оказались ошибкой параллельных запросов в исходном Bullet. В изолированном префиксе **495 кадров** сериализация только рабочего стека исходного broad phase восстановила **все флаги попаданий стоп и пальцев** до точного совпадения с Jolt v11. Геометрия, маски и callback исходного движка остались прежними. Производственный код Jolt не менялся.

## Измеренная конкуренция

`WorldObjects::updateAnimation` вызывает обновление NPC через `parallelTasks(npcArr)`; Foot IK при этом вызывает `world->ray`. Исходный `CollisionWorld::Broadphase::rayTest` использует один `rayTestStk` для обоих деревьев broad phase без блокировки. Счётчик ставился непосредственно вокруг нативных обходов; сообщение печаталось после обхода, чтобы логирование не сериализовало вход.

В логе зарегистрированы **128 перекрывающихся обходов** — установленный лимит сообщений. Максимальное наблюдённое число одновременно активных обходов равно **6**; события содержат **9 разных идентификаторов потоков**, один экземпляр broad phase и один адрес общего стека. Это измерение параллельного использования одного стека, а не вывод только по исходному коду. Отдельный временный эталон добавлял mutex исключительно вокруг этих исходных обходов.

## Сверка неизменного сценария

Все варианты использовали исходный `foreach stairs 8`, одинаковую подготовку и пошаговый клиент `--stdio`; остановка после седьмого `rec_stop` сохранила первые **495 строк**. Координаты героя совпали точно между всеми тремя диагностическими вариантами.

| Флаг | Исходный Bullet с трассировкой против Jolt | Исходный Bullet с сериализацией против Jolt |
| --- | ---: | ---: |
| Левая стопа `l_has` | 17 | 0 |
| Правая стопа `r_has` | 9 | 0 |
| Левые пальцы `l_toehas` | 16 | 0 |
| Правые пальцы `r_toehas` | 10 | 0 |

После сериализации также нет расхождений `bs`, `ik_valid`, `ik_on`, `ik_hardoff`, `ik_w`, `f_hits`, `hp_player` и `hp_subject`. Небольшие различия других вещественных метрик позы остаются; точного совпадения всех столбцов CSV эта проверка не утверждает.

Нулевая нормаль в исходно выбранных для расследования попаданиях означала категорию `C_Object`: игровая обёртка намеренно обнуляет нормали объектов. Она не доказывала вырожденный треугольник. После сериализации исходный Bullet тоже обнаруживал эти поверхности; воспроизводить случайные пропуски объектов или менять масштаб и геометрические допуски Jolt для этих флагов не требуется.

## Вариация исходного эталона и предел доказательства

Полные исходные прогоны v4 и v7, с одинаковой физикой и изменением защитной ветки шрифтов для headless-запуска, уже расходились на 1680 строках лестницы: **102/85** флага левой/правой стопы и **96/62** флага пальцев. В текущем несериализованном диагностическом прогоне против неизменного исходного v7 поменялись ещё **12/3** флага стоп и **9/5** флага пальцев при точных координатах героя. Дополнительные читающие запросы и логирование меняют расписание потоков; это наблюдаемое влияние диагностики сохранено, а не скрыто.

Сериализованный Bullet здесь служит только временным наблюдателем для причинной проверки. Он не включён в новый движок. Совпадение доказано для 495 кадров, включая первое позднее расхождение; полного сериализованного эталона на 1680 кадров эта проверка не создаёт. Нативные запросы Jolt остаются потокобезопасными, и новых изменений рабочего движка в этой области не требуется.
