# Предварительный протокол повторных замеров quad-wolf

Статус: подготовлен 2026-10-14, **ни один повтор по этому протоколу не запускался**. Цель — оценить наблюдаемую вариабельность того же wall-clock показателя без выбора удачного прогона. Первый результат v12 остаётся ошибкой timing gate: p95 229,231 мс против 226,061 мс исходного V7 (+1,402%); p50 10,443 против 13,965 мс. Причинная связь с scalar witness этим одним замером не установлена. Текущий gate не изменяется до получения полного набора ниже.

До первого запуска фиксируются SHA256 окончательного Jolt runner, его исходников/профилирования и этого протокола. Во всех пяти парах используется один и тот же неизменяемый кандидат. Исходный runner V7: `/home/kaifat/gothic-ai/physics-stage1/bullet-headless-v7/reference/opengothic/gothic-body-runner`, SHA256 `8dc934be2fb93de74217b580aaf6abc6f48606d41312fb8dc294b6eb63d0db3c`. Контактный safe-original с mutex не заменяет эту заранее выбранную временную контрольную группу.

Порядок десяти запусков зафиксирован заранее; каждый запуск получает новый каталог, отдельный процесс и исходный save:

Общие условия: `dev-ubuntu`, CPUQuota 200%, MemoryMax 12 GiB, TasksMax 128, headless lockstep 30 fps, seed 73013, без графики/аудио/моделей. Весь блок последователен под `body-simulation.lock`; игры, сборки и другие запланированные ресурсоёмкие задачи на хосте отсутствуют. Если хост до очередного запуска занят, порядок приостанавливается, а факт и время ожидания записываются; уже полученные данные сохраняются. Во время блока не меняются бинарники, ресурсы, профилирование, ассеты или сценарий.

Исходный save SHA256 — `c2852f4c009f23225e1c9c70f564ca36b4c12e8220736d1c72a1dbfce8d3372f`, ассеты — прежний неизменяемый `/home/kaifat/gothic-ai/body-baseline/assets`. Исходный `scripts/bench/quad-wolf.bench` SHA256 — `c557032afbe0c93c75f24193a4c6030c176bccb2e340e345667a1bce82982101`; после прежних `seed 73013` и `rec … novideo` эффективный сценарий обязан иметь SHA256 `9d47ec7504e2b92a3249d8b2626ae23e4f40035946c191e2995ce5619671fe99`. Стандартный scenario timeout — 900 секунд. Условия всех десяти запусков и их происхождение записываются до/при запуске.

Сохраняются все десять результатов: launcher/bench logs, exit code, runner summary, manifest, metrics/events, полный `physics-time.csv`, hashes и сведения о порядке. Проверки полноты/уникальности кадров, сценарных ошибок, исходов, конечных чисел и происхождения остаются прежними. Для каждого успешного полного запуска ожидаются 1260 записанных metric frames, 24 сегмента `w0…w5 × up/down/across/stand`, 1546 timing rows и 1514 прогретых timing samples. Запуск с ошибкой, усечением или иной структурой не исключается и не заменяется новым: итог блока получает `incomplete`/`failed`, pooled timing gate не объявляется пройденным. Остальные заранее назначенные запуски продолжаются, когда это возможно.

Из каждого полного `physics-time.csv` отбрасываются ровно первые 32 строки, как в действующем сравнивателе. Для каждого backend объединяются все оставшиеся `sample[1]` без фильтрации выбросов: **5 × 1514 = 7570 samples**. P50/p95 вычисляются прежним правилом `sorted_samples[int(p * (n - 1))]`, p = 0,5/0,95. Это тот же scope: tick и накопленное между ticks внешнее wall time публичных запросов/движения/transform, вложенные вызовы учтены один раз; показатель не заменяется временем всего runner, CPU time или иным clock.

Основной итог — pooled p50/p95 и их отношения Jolt/original. Дополнительно публикуются все пять пар и все десять индивидуальных p50/p95, число/cadence samples и wall time запусков. Лучшие пары, медиана пяти квантилей и удаление хвоста не заменяют заранее выбранную агрегацию. Timing gate проходит только при полном валидном блоке и **pooled Jolt p50 ≤ pooled original p50, pooled Jolt p95 ≤ pooled original p95**; структурные/поведенческие критерии проверяются отдельно по прежним правилам. Это не меняет исходный неудачный v12 результат и не закрывает остальные проверки этапа 1.
