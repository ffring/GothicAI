# Closest terrain ray source normals

Status: integrated in frozen v13. Mac game/editor/contracts passed. This report proves source-plane arithmetic on archived inputs; final Linux queries, movement, timing and E2E have their own verdicts.

The closest ray already refined its selected native face to the original plane's fraction and point, while exporting the decoded mesh normal. The preserved v12 heading diagnostic contains 107 paired landscape faces from 12 distinct source triangles. All original vertices match Bullet bit-for-bit. Scalar source cross/dot, `sqrtf`, then a separate float reciprocal multiplied into each component reproduces **107/107 Bullet normals, all 321 component bits**. The same source-plane calculation on Jolt's actual ray endpoints reproduces **107/107 refined public fractions**. Native decoded normals differ in every sampled face; maximum vector difference is **9.977514671893382e-6**.

An independent C++ float verifier, Apple clang 21 ARM64 with `-O2 -ffp-contract=off`, also matches all 107 normals. Replacing reciprocal multiplication with component division changes **37/107 samples**, spanning six of the twelve faces. The maintained `testSourceTerrainNormals` retains all twelve original vertex/expected-bit fixtures. `testTerrainRayNormalScope` checks identity closest-landscape output and native all-hit/object controls. Both ran in the [combined Mac build](../../../data/physics/stage1/jolt-final-v13/local-validation.json).

`PhysicVbo::rayTriangleNormal` accepts only an existing source triangle, finite vertices, finite positive scalar length squared and finite normalized output. It preserves source winding and leaves the output unchanged when invalid. Regression guards cover coincident/collinear faces, float area underflow/overflow, infinity/NaN and an invalid triangle ID. Source-fraction checks retain the existing parallel, endpoint, backface and outside-triangle rejection.

The integration is limited to closest queries with a valid original fraction **0 < f < 1**, category `C_Landscape`, identity body rotation and unit scale. Fraction/point/normal refer to the same final selected/resolved original triangle. All-hit ordering, fractions and normals stay in their native branch; object normals and Jolt contact generation/solver are unchanged. `DynamicWorld::toResult` continues to export zero object normals for movement.

Of the 194 paired ground outputs, 107 propagate the face-scope normal differences and the other 87 already match. The logger does not contain direct NPC fall-cache snapshots or decoded child vertex positions. Only 51 of 107 paired rays still have identical endpoints after earlier movement divergence; normal arithmetic is independent of the ray position. This does **not** establish that decoded-normal differences caused wolf leg yaw or that the refinement fixes the full movement suite.
