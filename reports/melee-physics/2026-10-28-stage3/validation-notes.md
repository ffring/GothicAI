# Физическая боёвка, этап 3 — логика

**Статус: blocked. Две проверки механики не дали штатного завершения подъёма.** Дальнейшие исправления и игровые прогоны остановлены по стоп-правилу. Код не принят; флаг по заданию включён по умолчанию.

## Код и числа

- `[GAME] melee_posture=0` / Marvin `toggle melee_posture` выключают механизм; `MELEE_POSTURE` передаётся через `bench.sh`, `e2e.sh`, `ryzen.sh`.
- Общая `OpenGothic/common/game/meleeimpact.*`: `J = velocity_cm_s / 100 × mass × (0,5 + 0,5 × sin(angle))`, модуль 0…40 Н·с. Масса кулака / одноручного / двуручного с рукой — **1,5 / 2,5 / 4 кг**. `MeleeBladeContact::velocityCmS` — мировой вектор; прежний порядок вычисления `speedCmS` сохранён. Legacy берёт `0,7 × MAN_peak`, при выключенных обоих клинковых флагах — номинальные **500 / 800 / 1000 см/с**, направление от атакующего к цели, угол 90°.
- Люди, включая героя: шкала 0…100, добавка `100 × |J| / (40 × physicsMass()/75)`, восстановление 30/с после 1,5 с без ударов. Блок не накапливает шкалу. StumbleA/B сохранены. Монстры исключены.
- Нокдаун создаёт полное тело без вызова KO; лежащий не атакует и не блокирует, обычный урон остаётся. Подъём запрашивается через существующие `recoverRagdoll` и `S_WOUNDED/B`; после возврата управления шкала 0, иммунитет 4 с с пределом 60. Работает прежняя точка возврата NPC; для принудительного подъёма над провалом выбирается она.
- Сейв не пишет шкалу, тело и overlay нокдауна; координаты сохраняются в исходной точке падения, под телом оставлена обычная Idle. Холодная загрузка **не проверена**.
- Журнал `melee-posture.jsonl`: импульс, зона, шкала, участники, нокдаун, время падения/начала подъёма/возврата управления, `returned`, `forced`; seed связывает записи с дуэлью. `knockdown_health` отдельно проверяет HP до/после создания тела и `isUnconscious` после него.
- P30, признаки, обучение, протокол, сервер и код вида тела не менялись.

## Почему остановлено

Ryzen, native, только ON, `melee_physics_hits=1`, 300 HP, сиды **100000…100063**, чередующиеся стороны, предел **60 с**. После первой проверки изменён запрос Idle: повторять до принятия, затем дать переходу закончиться. Во второй проверке запрос принимался через **1200 мс**, но стояние так и не подтверждалось до отсечки. Первоначальная гипотеза об отклонении запроса не подтвердилась; причина незавершения штатного пути не установлена. Вид тела не оценивался и не настраивался.

| 2, после исправления | 64 | 186 / 169 | 0 / 169, явный `forced=true` | 3967…4000 | 0 / 186 |

Диагностическая строка второй проверки, роль BDT: **37 побед / 27 поражений / 0 таймаутов**, среднее **25,156 с**, **2,906 нокдауна/дуэль**; **10/186 = 5,376%** нокдаунов завершились поражением упавшего за 3 с. Это не приёмка OFF/ON. OFF — **0 дуэлей**, P30 — **0 завершённых**; оба пакета остановлены до его результатов.

Данные двух проверок перенесены со сверкой на `/mnt/shared/gothic-ai/e2e/claude-melee-3-posture/runs/duels-stage3-{warm,second}/`. Первый холодный запуск до дуэлей отверг `fork-reset` из-за многопоточного шаблона; с явной готовой базой своей задачи runner работал. Это ошибка подготовки, не попытка механики.
