# Eval: decision-модели для реакций NPC

Проверяем, может ли маленькая локальная decision-модель (как Jev) вместо `gpt-6.1-sol` решать, как NPC реагирует на событие. Контекст и выбор кандидатов: [research_notes/npc_decision_models.md](../../research_notes/npc_decision_models.md).

## Набор

[situations.yaml](situations.yaml) — 76 сцен из Gothic 2: стража, торговцы, кражи, память о прошлых встречах, реплики героя по-русски, выбор предмета, NPC или места, ситуации «лучше ничего не делать». Варианты `svm_*` — родные озвученные фразы из `OU.BIN`.

Каждой сцене задаём три вопроса, кое-где ещё четвёртый:
- `react` (choice) — что NPC делает сейчас, 3–5 вариантов;
- `think` (noul) — нужен ли продуманный ответ большой модели;
- `attitude` (score) — как изменилось отношение к герою, 5 уровней;
- `extra` (choice, 6 сцен) — параметр действия: предмет, кого звать, куда идти.

Эталон расставлен вручную (Claude) по смыслу сцены, для спорных случаев есть список приемлемых ответов. Ответы `gpt-6.1-sol` совпали с эталоном в 99% по `react`, так что эталон согласован с сильной моделью. Но и смещён в её сторону.

Условия:
- `en` — состояние по-английски, реплики героя по-русски;
- `ru` — всё состояние по-русски;
- `en_rev` — как `en`, но варианты в обратном порядке.

Вопросы и варианты всегда по-английски.

## Как запускать

```bash
uv run build.py                                                   # situations.yaml -> requests.jsonl, gold.json
scp run_decider.py requests.jsonl dev-ubuntu:gothic-ai/decider-eval/
ssh dev-ubuntu 'cd ~/gothic-ai/decider-eval && .venv-strands/bin/python run_decider.py strands'
uv run --project ../../server python run_gpt.py --cond en         # эталонная модель, ~19 вызовов подписки
python3 score.py                                                  # preds/ -> results.md
```

На dev-ubuntu у каждой модели свой venv (`~/gothic-ai/decider-eval/setup.sh`), веса OpenJev лежат в `~/gothic-ai/decider-eval/openjev/`.

## Результаты (2026-10-11, RTX 3090)

Полные таблицы: [results.md](results.md).

| модель | react ✓ en | react ✓ ru | уверенность ≥ 0,7: охват / верно | attitude ±1 | extra | запрос p50 | память |
|---|---|---|---|---|---|---|---|
| `gpt-6.1-sol` (low, подписка) | 99% | — | — | 100% | 6/6 | ~1,8 с на ситуацию (7,2 с на 4) | — |
| **Strands Decider 2B** | **86%** | 71% | 42% / 97% | 92% | 5/6 | **98 мс** | 3,8 ГБ |
| OpenJev 4B v5 | 83% | 79% | 32% / 100% | 95% | 5/6 | 271 мс | 9,1 ГБ |
| OpenJev 2B v5 | 80% | 72% | 17% / 100% | 87% | 3/6 | 120 мс | 4,4 ГБ |
| Laya (Router) | 58% | 45% | 25% / 63% | 82% | 3/6 | 11 мс | 4,4 ГБ |

Задержка — на один запрос из 3–4 вопросов, без оптимизированных ядер `flash-linear-attention` и `causal_conv1d`.

**Выводы:**
- **Лучший кандидат — Strands Decider 2B.** Самая высокая точность, 0,1 с на запрос, меньше 4 ГБ видеопамяти.
- **Состояние надо писать по-английски.** На русском Strands теряет 15 п. п. OpenJev 4B к языку устойчивее (−4 п. п.), но втрое медленнее и вдвое тяжелее.
- **Сильные стороны.** Инициатива, память, выбор параметра, ответы на вопросы героя: у Strands 87–100%.
- **Провал — угрозы и преступления: 45% у всех локальных моделей.** Ошибки системные:
  - модели **уступают требованию героя**: отдают деньги под угрозой, пропускают «посланника паладинов», продают зелье за 5 золотых;
  - **не доводят до атаки** после двух предупреждений;
  - **игнорируют характер**: трусливые Валентино и Секоб «атакуют».

  Ровно эти ситуации уже обрабатывают скрипты игры (реакция на оружие, кражу, магию). Слою «рефлексов» их отдавать не надо.
- **Порог уверенности работает.** При уверенности ≥ 0,7 Strands отвечает в 42% случаев и прав в 97% из них. При ≥ 0,9 прав всегда, но отвечает лишь в 12% случаев.
- **Вопрос `think` модели не тянут.** Strands почти всегда отвечает «да» (35 ложных из 52), AUROC 0,77. Звать большую модель лучше по правилу: герой обратился к NPC — значит, это разговор.
- **Порядок вариантов.** Strands меняет ответ при обратном порядке в 12% сцен, хотя авторы обещают независимость. У OpenJev ответ от порядка не зависит.

**Ограничения.** Сцен всего 76, разброс около ±8 п. п. Эталон расставлял один разметчик.

## Новые версии Strands (2026-10-11)

Все три версии на той же основе Qwen3.5-2B, прогон с ядрами (`.venv-strands-fast`):

| версия | react ✓ en / ru / en_rev | ≥ 0,5: охват / верно / итог | ≥ 0,9: охват | угрозы | тишина (noop) | extra | запрос p50 |
|---|---|---|---|---|---|---|---|
| `hobson-v19` (была) | 86 / 70 / 83% | 61 / 91 / 64% | 12% | 45% | 91% | 5/6 | 84 мс |
| **`qwen3.5-v1-2610`** | **86 / 80 / 89%** | **68 / 96 / 75%** | **21%** | **55%** | 73% | 4/6 | 86 мс |
| `hobson-v21` | 83 / 70 / 82% | 55 / 90 / 59% | 5% | 45% | 82% | 5/6 | 84 мс |

**Берём `v1-2610`.** Чем она лучше v19:
- на русском состоянии +10 п. п.;
- уверенность честнее: больше сцен проходит порог, и они верны;
- меньше зависит от порядка вариантов (92% против 88%);
- лучше на угрозах.

Где она хуже:
- лишний раз действует там, где надо ничего не делать: «будит» спящих, в одной сцене с уверенностью 0,73;
- Мильтен идёт к воротам вместо зала Гаронда.

LoRA у неё rank 48 против 16 у v19, но скорость та же.

## Дообучение на сценах Готики (2026-10-11)

`v1-2610` дообучили на 864 ответах `gpt-6.1-sol` по 392 сгенерированным сценам ([decider-service/tuning](../../decider-service/tuning/README.md)). NPC из этого набора в обучении не было.

| модель | react ✓ en / ru / en_rev | ≥ 0,5: охват / верно / итог | ≥ 0,7: охват / верно | угрозы | тишина (noop) |
|---|---|---|---|---|---|
| `qwen3.5-v1-2610` | 86 / 80 / 89% | 68 / 96 / 75% | 42 / 97% | 6/11 | 8/11 |
| `tuned-g1`, 3 эпохи | 97 / 96 / 99% | 72 / 100 / 76% | 51 / 100% | 11/11 | 11/11 |
| **`tuned-g2`, 2 эпохи** | 95 / 93 / 96% | **88 / 99 / 88%** | **76 / 100%** | 9/11 | 11/11 |

Для планировщика лучше g2: при пороге 0,5 она правильно действует в 88% сцен. У g1 точность чуть выше, но после переобучения калибровка занижает уверенность. Скорость и память не изменились.

Потом добавили 227 карточек про происшествия и про личные дела NPC с героем, а также вопрос `escalate` — звать ли большую модель. Получилась **`tuned-g5`**, лучшая по реакции:
- react ✓ en / ru / en_rev — 97 / 95 / 97%;
- при пороге 0,5 охват / верно / итог — 89 / 99 / 89%.

Для `escalate` ручной эталон по этим сценам лежит в [escalate_gold.yaml](escalate_gold.yaml). У g5 уровень попадает в ±1 в 97% сцен, AUROC «звать» — 0,79. Мой эталон и `gpt-6.1-sol` сами сходятся в «звать / не звать» в 84% сцен. Подробности — [decider-service/tuning](../../decider-service/tuning/README.md).

## Нагрузка: сколько NPC тянет одна 3090 (2026-10-11)

Скрипты:
- [load_test.py](load_test.py) — пачки, живая нагрузка, всплески;
- [island_test.py](island_test.py) — мощность при разном числе вопросов и уровни для всего острова.

Сырые результаты лежат в [load/](load/).

**Как устроен тест.** Запросы многих NPC идут за один проход модели: каждая пара «состояние + вопрос» — строка пачки, не больше 8192 токенов за проход, памяти не больше 9 ГБ. Ответы совпадают с обычным режимом в 76 из 76 сцен, вероятности расходятся не больше чем на 0,011. Состояние короткое (~50 токенов, как в наборе) или длинное (~200 токенов: плюс 10 фактов памяти).

**Ядра обязательны.** Без `flash-linear-attention` и `causal-conv1d` слои Gated DeltaNet в Qwen3.5 считаются запасной реализацией. С ядрами (окружение `.venv-strands-fast`, `causal-conv1d` собирается из исходников ~7 минут) мощность растёт в 1,3 раза.

**Предел пачками, запросов в секунду:**

| вопросов в запросе | короткое состояние | длинное состояние | один запрос (короткое / длинное) |
|---|---|---|---|
| 3–4 (весь набор), без ядер | 17,6 | 9,6 | 85 / 134 мс |
| 3–4 (весь набор) | 23,7 | 12,8 | 64 / 102 мс |
| 2 (`react` + `attitude`) | 36 | 20 | 49 / 74 мс |
| **1 (`react`)** | **82** | **42** | **33 / 38 мс** |

Стоимость почти пропорциональна числу строк: каждый вопрос заново прогоняет состояние вместе со своим текстом и вариантами. Пачки поднимают мощность лишь в 2–2,5 раза по сравнению с запросами по одному.

**Живая нагрузка** (весь набор вопросов; у каждого NPC запросы со случайными интервалами, среднее указано в таблице; очередь собирает в пачку всё, что ждёт):

| NPC | событие раз в | короткое: медиана / p95 | длинное: медиана / p95 |
|---|---|---|---|
| 10 | 5 с | 61 / 108 мс | 98 / 187 мс |
| 25 | 5 с | 61 / 138 мс | 102 / 372 мс |
| 50 | 5 с | 104 / 498 мс | 359 мс / 1,35 с |
| 100 | 5 с | 1,3 / 2,8 с | 3,6 / 5,7 с |
| 50 | 2 с | 0,65 / 1,5 с | 2,3 / 3,3 с |
| 100 | 2 с | 2,7 / 3,7 с | 6,0 / 7,2 с |

**Всплеск:** все NPC спрашивают одновременно, весь набор вопросов. 50 NPC получают ответ за 2,2 с (короткое состояние) или 3,9 с (длинное).

**Весь остров по уровням** ([island_test.py](island_test.py), 60 с на сценарий, ближние первыми в очереди, в пачке не больше 32 запросов):

| сценарий | нагрузка | ближние: медиана / p95 | средние | дальние |
|---|---|---|---|---|
| «в лоб»: 6 ближних раз в 0,5 с, 20 средних раз в 5 с, 125 дальних раз в 20 с; весь набор вопросов, длинные состояния | 12 запросов/с, предел | 1,6 / 4,1 с | 1,7 / 3,9 с | 2,0 / 4,7 с |
| **остров: 8 ближних раз в 2 с (`react` + `attitude`), 30 средних раз в 10 с (`react`), 250 дальних раз в 60 с (`react`)** | **13,6 запроса/с** | **76 / 186 мс** | **55 / 148 мс** | **49 / 158 мс** |
| остров, ближние раз в 0,5 с, средние раз в 5 с, дальние раз в 20 с | 27,8 запроса/с | 530 мс / 1,0 с | 567 мс / 1,0 с | 590 мс / 1,1 с |

**Выводы:**
- **Остров тянем.** 288 NPC укладываются в треть мощности с задержкой меньше 0,2 с, если соблюдать три правила:
  - в плановых проверках задавать один вопрос;
  - ближних опрашивать по событиям, а не каждые 0,5 с;
  - дальним задавать решения уровня «чем заняться», раз в минуту.
- **Приоритет без ограничения пачки не помогает.** Срочный запрос ждёт, пока доработает уже запущенная большая пачка: 32 длинных запроса с полным набором — это ~2,5 с. Пачку надо ограничивать по времени выполнения, например 100–150 мс, а не по числу запросов.
- **Разовые выбросы до 0,7–1,4 с** — вероятно, компиляция Triton-ядер под новую форму данных. Нужен прогрев на типовых размерах при старте.
- **Voxtral (ASR) на той же видеокарте** во время теста не проверяли. Нагрузку decider лучше держать ниже ~50% мощности.
